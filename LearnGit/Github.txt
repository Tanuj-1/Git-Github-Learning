# GitHub – Complete Notes

## 1. What is GitHub?

GitHub is a **cloud-based platform** used to store, manage, share, and collaborate on software projects using **Git**.

GitHub mainly provides:

* Remote repositories
* Code hosting
* Collaboration
* Pull Requests
* Code Review
* Issue Tracking
* Branch Management
* Project Management
* Open Source Collaboration

**Simple Definition:**

> GitHub is an online platform where developers store Git repositories and collaborate on projects.

---

# 2. Git vs GitHub

| Git                           | GitHub                         |
| ----------------------------- | ------------------------------ |
| Version Control System        | Cloud-based platform           |
| Works mainly on local machine | Works online                   |
| Tracks code changes           | Hosts Git repositories         |
| Created by Linus Torvalds     | Owned by Microsoft             |
| Can work without internet     | Usually requires internet      |
| Command-line/tool             | Web platform + Git integration |

### Example

```text
Git = Tool
GitHub = Online Platform
```

---

# 3. Repository

A **Repository (Repo)** is a project folder managed by Git.

It contains:

* Source code
* Git history
* Branches
* Commits
* README
* Configuration files

Example:

```text
E-Commerce-Project/
│
├── src/
├── pom.xml
├── README.md
└── .git/
```

---

# 4. Local Repository

Repository present on your computer.

Example:

```text
C:\Users\Tanuj\ECommerceProject
```

---

# 5. Remote Repository

Repository stored online, usually on GitHub.

Example:

```text
GitHub
   ↓
ECommerceProject
```

---

# 6. GitHub Repository Creation

Steps:

1. Open GitHub
2. Click **New Repository**
3. Enter repository name
4. Add description
5. Select Public/Private
6. Add README if required
7. Add `.gitignore` if required
8. Click **Create Repository**

---

# 8. Private Repository

Only authorized people can access the repository.

Useful for:

# 9. Clone

`git clone` copies a remote GitHub repository to your local computer.

```bash
git clone https://github.com/username/project.git
```

Example:

```bash
git clone https://github.com/Tanuj/project.git
```

After cloning:

```bash
cd project
```

---

# 10. GitHub Remote

A remote is a connection between the local repository and GitHub repository.

Common remote name:

```text
origin
```

Check remote:

```bash
git remote -v
```

Add remote:

```bash
git remote add origin https://github.com/username/project.git
```

Remove remote:

```bash
git remote remove origin
```

Change remote:

```bash
git remote set-url origin https://github.com/username/new-project.git
```

---

# 11. Push

Push sends local commits to GitHub.

```bash
git push
```

First push:

```bash
git push -u origin main
```

For another branch:

```bash
git push -u origin feature/login
```

---

# 12. Pull

Pull downloads the latest changes from GitHub and integrates them into the current local branch.

```bash
git pull
```

Example:

```bash
git pull origin main
```

---

# 13. Fetch

Fetch downloads changes from GitHub but does not automatically merge them into the current branch.

```bash
git fetch
```

Example:

```bash
git fetch origin
```

### Difference

```text
git fetch
↓
Download changes only

git pull
↓
Fetch + Merge
```

# 25. Pull Request (PR)

A Pull Request is a request to merge changes from one branch into another branch.

Example:

```text
feature/login
      ↓
     Push
      ↓
GitHub
      ↓
Pull Request
      ↓
Code Review
      ↓
Approval
      ↓
Merge
      ↓
main
```

---

# 26. Pull Request Workflow

```bash
git switch -c feature/login

# Make changes

git add .

git commit -m "Added login feature"

git push -u origin feature/login
```

Then on GitHub:

```text
Compare & Pull Request
        ↓
Create Pull Request
        ↓
Code Review
        ↓
Approval
        ↓
Merge Pull Request
```

---

# 27. Code Review

Code Review means another developer checks your code before merging.

Reviewers check:

* Code quality
* Bugs
* Security
* Naming
* Performance
* Logic
* Project standards

---

# 28. Merge

Merge combines changes from one branch into another.

Example:

```bash
git switch main
git merge feature/login
```

---

# 29. Fast-Forward Merge

Occurs when branches have not diverged.

```text
main
 A
  \
   B
    \
     C
```

Main pointer simply moves forward.

No separate merge commit is required.

---

# 30. Three-Way Merge

Occurs when both branches have different commits.

```text
       B---C  feature
      /
A---- 
      \
       D---E  main
```

Git uses:

* Common ancestor
* Current branch
* Incoming branch

Usually creates a merge commit.

---

# 31. Squash Merge

Combines multiple feature commits into one commit.

Example:

```text
Before:

commit 1
commit 2
commit 3
commit 4

After Squash:

Add Login Feature
```

Command:

```bash
git merge --squash feature/login
git commit -m "Add login feature"
```

---

# 32. Rebase

Rebase moves/replays commits on top of another branch.

```bash
git switch feature/login
git rebase main
```

Then:

```bash
git switch main
git merge feature/login
```

Rebase usually produces a cleaner linear history.

**Important:** Avoid rebasing shared/public branches unless the team workflow explicitly allows it because it rewrites commit history.

---

# 33. Merge Conflict

A merge conflict occurs when Git cannot automatically decide which changes to keep.

Example:

```text
Developer A → login.java
Developer B → login.java

Both modify the same lines
          ↓
      Conflict
```

Conflict markers:

```text
<<<<<<< HEAD
Your Code
=======
Other Branch Code
>>>>>>> feature/login
```

Fix manually, then:

```bash
git add .
git commit -m "Resolve merge conflict"
```

# 35. Fork

A fork creates your own copy of another person's GitHub repository under your GitHub account.

Commonly used in:

* Open Source
* Contributing to projects

Example:

```text
Original Repository
        ↓
       Fork
        ↓
Your GitHub Repository
```

---

# 36. Fork vs Clone

### Fork

Creates a copy on GitHub.

```text
GitHub → Your GitHub
```

### Clone

Copies repository from remote to your computer.

```text
GitHub → Local Computer
```

Example:

```text
.project
.settings/
```


```text

API Keys
Database Credentials
Private Tokens

```

# 44. GitHub Authentication

GitHub no longer uses normal account passwords for Git operations over HTTPS.

Common authentication methods:

* Personal Access Token (PAT)
* SSH
* GitHub CLI
* Credential Manager

---

# 45. Personal Access Token (PAT)

PAT can be used instead of a password for HTTPS Git operations.

Basic concept:

```text
Git
 ↓
GitHub
 ↓
Authentication
 ↓
Personal Access Token
```

Never share your token publicly.

---

# 46. SSH

SSH allows secure authentication with GitHub without repeatedly entering credentials.

Basic setup:

```bash
ssh-keygen -t ed25519 -C "your-email@example.com"
```

Then add the public key to GitHub.

Test:

```bash
ssh -T git@github.com
```
